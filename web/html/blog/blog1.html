Introduction to Docker

How containers and images turn applications into portable, repeatable units.

Learning relevance: Containers and images

What is Docker?

Docker is a platform for building, packaging, and running applications in containers. A container bundles application code with its runtime, libraries, and configuration, so the software behaves the same way on a laptop, a test server, or a production cluster.

Images and containers

Two terms sit at the heart of Docker. An image is a read-only template built from a set of instructions, typically written in a Dockerfile. A container is a running instance of that image. One image can start many containers, and each one is isolated from the others and from the host system. 

docker build -t my-app:1.0 .
docker run -d -p 8080:80 my-app:1.0

Why use Docker?

Containers help developers create consistent environments for development and deployment. The main benefits are:

  • Consistency: the same image runs identically across machines.
  • Isolation: each container has its own filesystem and dependencies.
  • Speed: containers start in seconds and use fewer resources than virtual machines.
  • Portability: images can be stored in a registry and deployed almost anywhere.
